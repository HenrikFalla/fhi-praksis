Publisering til GitHub Pages med GitHub Actions

Steg 1: Klargjør ditt eget HTML/CSS/JS-prosjekt

Steg 1

Start med ditt eget nettsideprosjekt (eller lag en ny mappe med en enkel index.html). For at GitHub Pages skal fungere på en gratis GitHub-konto, må repositoriet ditt på GitHub være satt til Public.

  1. Sørg for at prosjektet ditt har en index.html-fil i rotmappen (eller i en kjent undermappe).
  2. Opprett et nytt, Public repository på github.com/new dersom du ikke allerede har et.
  3. Koble prosjektmappen din til GitHub og push koden til main-branchen:
Terminal ( i ditt eget prosjekt ) Kopier kode 
git add .
git commit -m "Første versjon av nettsiden"
git branch -M main
git push -u origin main

Steg 2: Aktiver GitHub Pages i innstillingene

Steg 2

Før en GitHub Actions-workflow får lov til å publisere nettsiden din, må du fortelle GitHub at GitHub Actions skal brukes som kilde for GitHub Pages.

  1. Gå til repositoriet ditt på GitHub i nettleseren.
  2. Klikk på Settings i toppmenyen.
  3. I menyen til venstre (under Code, planning, and automation), klikk på Pages.
  4. Under Build and deployment → Source, bytt fra Deploy from a branch til GitHub Actions.

Tips: Innstillingen lagres automatisk så snart du velger GitHub Actions i nedtrekksmenyen. Ignorer forslagene til ferdige workflows som GitHub viser på siden — vi lager vår egen fil i neste steg.

Steg 3: Opprett GitHub Actions-workflow

Steg 3

GitHub Actions ser etter YAML-filer i mappen .github/workflows/ i roten av repositoriet ditt. For en vanlig statisk nettside med ren HTML, CSS og JavaScript trenger vi ikke noe byggesteg — vi kan laste opp filene direkte.

YAML (YAML Ain't Markup Language) er et menneskelesbart dataserialiseringsspråk, designet for datautveksling mellom språk med ulike datastrukturer. Lær mer

  1. I ditt eget prosjekt, opprett mappen .github/workflows (husk punktumet foran .github).
  2. Opprett filen .github/workflows/deploy.yml og lim inn følgende oppsett:
.github/workflows/deploy.yml Kopier kode 
name: Publiser til GitHub Pages

# Når skal denne workflowen kjøre?
on:
  # Kjør automatisk ved push til main-branchen
  push:
    branches: ["main"]

  # Gjør det mulig å starte workflowen manuelt fra Actions-fanen på GitHub
  workflow_dispatch:

# Tillatelser som trengs for å publisere til GitHub Pages
permissions:
  contents: read
  pages: write
  id-token: write

# Sikrer at kun én publisering kjører om gangen
concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Sjekk ut koden fra repositoriet
        uses: actions/checkout@v4

      - name: Konfigurer GitHub Pages
        uses: actions/configure-pages@v5

      - name: Last opp filer som Pages-artifact
        uses: actions/upload-pages-artifact@v4
        with:
          # '.' betyr rotmappen i repositoriet ditt.
          # Hvis index.html ligger i en undermappe (f.eks. 'src/'), endrer du '.' til './src'
          path: "."

      - name: Publiser til GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

Hva betyr de viktigste delene i filen?

  • on: push: branches: ["main"]: Starter workflowen automatisk hver gang du pusher til main.
  • workflow_dispatch: Gir deg en "Run workflow"-knapp under Actions-fanen på GitHub.
  • permissions: Gir jobben lesetilgang til koden (contents: read) og tillatelse til å rulle ut til GitHub Pages (pages: write og id-token: write).
  • actions/upload-pages-artifact@v4: Pakker sammen alle filene i path: "." til en pakke klar for publisering.
  • actions/deploy-pages@v4: Publiserer pakken og gjør nettsiden tilgjengelig på din github.io-adresse.

Dersom HTML-, CSS- og JS-filene dine ligger i en undermappe i repositoriet (for eksempel ./min-undermappe):

  1. Workflow-filen .github/workflows/deploy.yml må alltid ligge i rotmappen av Git-repositoriet (ikke inne i undermappen).
  2. Endre path: "." under actions/upload-pages-artifact@v4 til stien for undermappen din, f.eks. path: "./min-undermappe".

Commit og push .github/workflows/deploy.yml til GitHub:

Terminal Kopier kode 
git add .github/workflows/deploy.yml
git commit -m "Legg til GitHub Actions workflow for GitHub Pages"
git push origin main

Steg 4: Test automatisk publisering (CI/CD i praksis)

Steg 4

Nå skal du sjekke at nettsiden din er publisert og teste at nye endringer ruller ut automatisk.

  1. Gå til Actions-fanen i repositoriet ditt på GitHub.
  2. Klikk på kjøringen for Publiser til GitHub Pages. Når steget deploy har fått en grønn hake, står nettadressen til siden din rett under jobben (f.eks. https://<brukernavn>.github.io/<repo-navn>/).
  3. Åpne nettadressen i nettleseren og bekreft at siden din vises.
  4. Gjør en synlig endring i din egen index.html eller styles.css lokalt, og push endringen til GitHub:
Terminal Kopier kode 
git add .
git commit -m "Oppdater innhold på nettsiden"
git push origin main

Vent til den nye kjøringen under Actions blir grønn, og last inn nettsiden på nytt (Ctrl + F5 / Cmd + Shift + R).

Steg 5 (Valgfritt): Byggesteg med npm og Vite

Valgfritt

Bruker prosjektet ditt npm-pakker (som f.eks. @folkehelseinstituttet/designsystem) eller et byggeverktøy som Vite? Da kan ikke nettleseren lese node_modules direkte. I stedet må GitHub Actions installere pakkene og kjøre npm run build før den ferdigbygde dist/-mappen publiseres.

1. Sett relativ base-sti i Vite

På GitHub Pages ligger prosjektet gjerne på en undermappe i URL-en (/<repo-navn>/). Legg til vite.config.js med base: "./" slik at lenker til CSS- og JS-filer fungerer uansett hva repositoriet heter:

vite.config.js Kopier kode 
import { defineConfig } from "vite";

export default defineConfig({
  base: "./",
});

2. Utvid workflowen med Node.js og byggesteg

Bytt ut innholdet i .github/workflows/deploy.yml med denne versjonen som kjører npm ci og npm run build, og laster opp ./dist:

.github/workflows/deploy.yml (med npm build) Kopier kode 
name: Bygg og publiser til GitHub Pages

on:
  push:
    branches: ["main"]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Sjekk ut koden fra repositoriet
        uses: actions/checkout@v4

      - name: Sett opp Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: "npm"

      - name: Installer avhengigheter
        run: npm ci

      - name: Bygg prosjektet
        run: npm run build

      - name: Konfigurer GitHub Pages
        uses: actions/configure-pages@v5

      - name: Last opp dist-mappen som Pages-artifact
        uses: actions/upload-pages-artifact@v4
        with:
          path: "./dist"

      - name: Publiser til GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

3. Ligger npm/Vite-prosjektet i en undermappe?

Hvis package.json og package-lock.json ikke ligger i rotmappen av repositoriet, men inne i en undermappe (f.eks. ./min-undermappe), må du gjøre tre tilpasninger i .github/workflows/deploy.yml:

  1. Legg til defaults.run.working-directory på jobben slik at npm ci og npm run build kjøres inne i undermappen.
  2. Legg til cache-dependency-path under actions/setup-node@v4 slik at den finner package-lock.json i undermappen.
  3. Oppdater path under actions/upload-pages-artifact@v4 til "./min-undermappe/dist".
.github/workflows/deploy.yml (npm build i undermappe) Kopier kode 
jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    # 1. Kjør kommandoer (npm ci, npm run build) i undermappen:
    defaults:
      run:
        working-directory: ./min-undermappe
    steps:
      - name: Sjekk ut koden fra repositoriet
        uses: actions/checkout@v4

      - name: Sett opp Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: "npm"
          # 2. Pek til package-lock.json i undermappen:
          cache-dependency-path: "./min-undermappe/package-lock.json"

      - name: Installer avhengigheter
        run: npm ci

      - name: Bygg prosjektet
        run: npm run build

      - name: Konfigurer GitHub Pages
        uses: actions/configure-pages@v5

      - name: Last opp dist-mappen som Pages-artifact
        uses: actions/upload-pages-artifact@v4
        with:
          # 3. Last opp dist-mappen fra undermappen:
          path: "./min-undermappe/dist"

      - name: Publiser til GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

Vanlige feil og feilsøking

Tips
  • Workflowen starter ikke når jeg pusher: Kontroller at filen heter nøyaktig .github/workflows/deploy.yml (plassert i rotmappen av repositoriet) og at branchen din heter main (hvis den heter master, endre branches: ["main"] i YAML-filen).
  • Jobben feiler på Configure eller Deploy Pages: Dobbeltsjekk Steg 2 — under Settings → Pages → Source må det stå GitHub Actions, og repositoriet må være Public. Pass også på at du bruker actions/upload-pages-artifact@v4 (og ikke vanlig actions/upload-artifact).
  • Nettsiden viser 404 Not Found: Sjekk at index.html ligger i mappen som path peker til i actions/upload-pages-artifact@v4 ("." for rotmappen, "./dist" ved bruk av Vite, eller "./min-undermappe" dersom prosjektet ligger i en undermappe).
  • Feilen Dependencies lock file is not found (i Steg 5): Pass på at package-lock.json er committet og pushet. Hvis prosjektet ligger i en undermappe, må du legge til cache-dependency-path under actions/setup-node@v4 og defaults.run.working-directory på jobben (se punkt 3 i Steg 5).
